# SQL-миграции PostgreSQL

Версионные forward-only миграции реляционной схемы (issue #336, О4). Чистые
SQL-миграции именуются `NNNN_<имя>.sql` с монотонно растущим числовым префиксом и
регистрируются в [`../registry.ts`](../registry.ts) в массиве `postgresMigrations`.

## Baseline

Нулевая миграция (`0001 baseline_schema`) — это монолитная схема
[`../../schema.sql`](../../schema.sql). Она остаётся в корне `db/`, потому что
исторически была единой точкой раскатки; реестр читает её как baseline с пометкой
`transactional: false` (содержит `ALTER TYPE … ADD VALUE`, несовместимый с
использованием значения в той же транзакции). Новые изменения схемы оформляйте
отдельными версионными файлами в этом каталоге, а не правкой `schema.sql`.

## Соглашения

- **Forward-only.** Уже зарелизенные файлы не редактируют.
- **Транзакционность.** По умолчанию миграция выполняется в одной транзакции
  вместе с записью в `schema_migrations`. Если миграция несовместима с
  транзакцией (например, `ALTER TYPE … ADD VALUE`, `CREATE INDEX CONCURRENTLY`),
  пометьте её в реестре `transactional: false`.
- **Data-миграции на TypeScript.** Сложные преобразования данных, которым нужен
  доступ к репозиториям ядра, оформляются как `.ts`-модули в каталоге `migrations/`
  (см. `M001_prompt_templates_to_schemas.ts`) и регистрируются обычной записью.

## Сборка

`scripts/copy-db-assets.mjs` копирует `*.sql` из этого каталога в
`dist/db/migrations/postgres/`, чтобы раннер мог читать их из собранного пакета.
